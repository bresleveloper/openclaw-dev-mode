# Upgrade playbook (dev-mode fork)

Read this in full before an upstream upgrade. It moved out of `CLAUDE.md` on 2026-11-11 so the always-loaded file stays small (Ariel: "maybe also clean and compact claude md?"). The everyday rules (README, no doctor, pushing, SSH, the dist force-add) stay in `CLAUDE.md`.

## Clean-room steps

- **Upgrades are clean-room**: branch from the upstream tag, re-apply the fork patches, build, then land the branch on `main` as ONE commit, no force push. Upstream's rewritten history never becomes reachable from `main`, so the VPS (`git pull origin main`) fetches only the new files (fetching it all took 13 min at 10.4).
  1. Fork patch (deletions left out; redo checklist items 1 and 9 instead): `git diff --binary --no-renames --diff-filter=AM v<prev-tag> main -- . ':!dist' ':!packages/ai/dist' ':!README.md' ':!CLAUDE.md' ':!dev-mode' ':!.github' ':!config/tsconfig/oxlint.source.json' ':!packages/tsconfig.json' ':!test/tsconfig/tsconfig.test.root.json'`. Classify per file with `git apply --cached --check` against a temp index (`GIT_INDEX_FILE=… git read-tree v<tag>`).
  2. Optional safety tag `git tag main-pre-<version> main`; `git checkout -b upgrade-<version> v<tag>`; the checklist below; `git apply --3way <patch>`; `git diff v<tag>` of every touched file, read in full (lessons below, 10.4); typecheck, format, lint, fork tests; full `pnpm build`; dist force-add.
  3. Land it: `git commit-tree <branch>^{tree} -p main -F <msg>`, `git update-ref refs/heads/main <new> <old>`, `git push origin main` (ask Ariel before pushing).
  4. Once the deploy works, delete the upgrade branch and any safety tag, locally and on GitHub: `git branch -D <name>` + `git push origin --delete <name>`; for a tag `git tag -d <name>` + `git push origin :refs/tags/<name>`.

## Post-Merge Cleanup Checklist (run after EVERY upstream merge)

1. **Remove the whole `.github/` directory**: `git rm -r .github`. Ariel's rule (2026-10-16): "anything that is running on GitHub delete, anything running local keep" — local tooling (git-hooks, pre-commit config, vitest/oxlint scripts, deploy manifests) stays; nothing in the build or at runtime reads `.github/`. The upstream tag has NO `dev-mode/`, no fork `README.md` and no fork `CLAUDE.md`: after branching from the tag, `git checkout main -- dev-mode README.md CLAUDE.md` (else the VPS recipe lacks `dev-mode/link-dist-plugin-deps.sh`). The vitest worker compiler copies `.github/workflows/plugin-npm-release.yml` as a worker asset and the whole compiled-subprocess build (every `|infra|`-style test) dies with ENOENT without it → fork guard in `scripts/lib/vitest-worker-compiler.mts` (skip missing assets); re-check it is still in the asset-copy loop.
2. **WhatsApp build exclusion**: the ONLY source is `package.json` `files` (`!dist/extensions/whatsapp/**`); `scripts/lib/root-package-bundled-plugin-excludes.mjs` derives the build excludes from it. Delete that line, or the build DELETES `dist/extensions/whatsapp` and the VPS falls back to the stock ClawHub package.
3. **Keep-ours on `README.md`**: Ariel's landing page, see "README is Ariel's domain" in `CLAUDE.md`.
4. **Stage dist — regular files only**: `find dist packages/ai/dist -type f > /tmp/dist-files.txt && git add -f --pathspec-from-file=/tmp/dist-files.txt`, then commit with `--no-verify` (the pre-commit formatter would rewrite generated files). Plain `git add -f dist/` also grabs ~300 symlinks the build's `external-plugins:local-dist` step leaves under `dist/extensions/*/node_modules/` (links into this machine's pnpm store) — never commit those. The real-file shim `dist/extensions/node_modules/openclaw/` (plugin-sdk) IS committed. See the ⚠️ in `CLAUDE.md` Build & Deploy.
5. **Re-verify patches survived**: grep `isDevMode()` anchors in src/; on the VPS after deploy `grep -rl attachWaHistoryLogger /opt/openclaw-dev-mode/dist/extensions/whatsapp/` and `grep -rl formatDevModeReasoningPayload /opt/openclaw-dev-mode/dist/extensions/whatsapp/` must be NON-empty.
6. **Self-referencing symlinks**: `pnpm install` creates UNTRACKED `node_modules/openclaw` links in ~40 workspace packages (ignored dirs git never traverses) — never `git add -f` anything under `node_modules/`.
7. **Stage `packages/ai/dist` with `git add -f packages/ai/dist/`** after every build (item 4's command covers it too): root `dependencies` has `"@openclaw/ai": "workspace:*"` and dist imports `@openclaw/ai/internal/*` at runtime. It is the ONLY workspace package dist imports at runtime (`@openclaw/session-url-contract` is a devDependency bundled into dist; `@openclaw/fs-safe`/`@openclaw/proxyline` are npm deps). On Windows the build leaves REAL directories (not symlinks) under `dist/extensions/*/node_modules/` — prune them: `find dist packages/ai/dist -path 'dist/extensions/*/node_modules' -prune -o -type f -print`. Re-check per upgrade: `grep -rhoE "from ['\"]@openclaw/[a-z0-9-]+" dist | sort | uniq -c` vs root `dependencies`.
8. **Re-read the upstream-owned hooks** listed in `CLAUDE.md` "Source Files Modified" and the regression checklists in the fork-owned files' headers.
9. **Delete upstream test files** (Ariel, 2026-10-16: "delete from our fork all upstream tests"; the fork's own tests and the local test tooling stay because they run locally). The fork keeps only its own 7 tests (listed in `CLAUDE.md` Build & Deploy). After branching from the tag: `git ls-files | grep -E '\.test\.(ts|tsx|mts|mjs|js)$' | grep -vE 'dev-mode/(echo-guard|reasoning)\.test|config-validate-fix\.test|config-content-fix\.test|dev-mode-greeting/handler\.test|fork-update-block\.test|fork-memory-provenance-trust\.test' > /tmp/t.txt && git rm -q --pathspec-from-file=/tmp/t.txt`; afterwards drop the deleted tests from the `files` lists of `config/tsconfig/oxlint.source.json`, `packages/tsconfig.json`, `test/tsconfig/tsconfig.test.root.json` and delete the orphan `test/tsconfig/tsconfig.crabline-candidate.json` (the only one at 11.3), or lint/tsgo fail on missing files. Test infrastructure stays (`test/` setup + helpers, `*.test-support.ts`, `*.test-harness.ts`, `test-helpers/`, `test-utils/`): the fork tests import some of it, and the tsgo configs already exclude all of it. Upstream's suites are never run in the fork; validate re-homed hooks by reading the diff and running the fork tests.

## Lessons from past upgrades

- **3.13**: a 15K-line WhatsApp refactor broke WA (echoes, dropped creds); rolled back to 3.11. Before any upgrade run `git diff --stat` on `extensions/whatsapp/` and test WA thoroughly if it is big.
- **5.12**: WhatsApp moved to ClawHub, so a managed install silently overrode the fork's patches (`wa-history.db` froze) → bundled build (checklist item 2).
- **7.1**: the Node floor went up (the build's last step runs the fresh CLI): don't auto-install Node on Ariel's machines, ask. `@openclaw/ai` became a runtime workspace dep → pnpm on the VPS + `packages/ai/dist` force-add (item 7). A tracked self-ref symlink (`packages/speech-core/node_modules/openclaw`) corrupted `.git` twice during checkouts (gone since 9.6). Startup-migration gates crash-looped the gateway on permanent warnings (legacy memory-core `.dreams/*.json`, a broken `openclaw-web-search` package); since 9.6 warnings only log, refusals are still fatal.
- **9.6**: upstream rewrote history (`v2026.7.1` is NOT an ancestor of `v2026.9.6`; don't trust tag-range counts). The port process that worked: parallel read-only analyses (per patch SEAMLESS / ADAPT / THINK / DROP with file:line) → port the confident set (`git apply --3way` for small hunks, manual re-homing otherwise) → Ariel decides the THINK items one by one → render the real dev-mode system prompt (`buildAgentSystemPrompt` via `node --import ./scripts/tsx.mjs`) and sweep runtime gates → docs. `acpx` failed on stale real `dist/extensions/*/node_modules` dirs → `dev-mode/link-dist-plugin-deps.sh`.
- **10.4**: upstream rewrote history again; fetching it onto the VPS took 13 min → the squash landing (clean-room steps above). The 10.4 gateway refused to start (exit status 78) on agent DBs at the old schema ("run openclaw doctor --fix to migrate session identities"; version constant `OPENCLAW_AGENT_SCHEMA_VERSION` in `src/state/openclaw-agent-db-contract.ts`, gate `assertCanonicalAgentPersistenceVersion` in `src/state/openclaw-agent-db-schema-read.ts`; no doctor flag limits a run to that step) → `dev-mode/migrate-agent-dbs.mts` plus DB copies first (the previous build refuses upgraded files). A failed start changes nothing; rollback = check out the old commit, `pnpm install`, `systemctl --user reset-failed openclaw-gateway`, start. `git apply --3way` applied a hunk "cleanly" that only made sense with its conflicted neighbour and dropped the `nowMs` line in `control-plane-rate-limit.ts` (SEC-78 had moved it): always `git diff v<tag>` every touched file and read it.
- **10.10** (ported, never built or deployed; 11.3 replaced it): added doctor-pointing ACP-metadata startup gates (`src/acp/runtime/session-meta-startup.ts`: embedded `acp` in `session_nodes.entry_json`, legacy keys in the state DB's `acp_sessions`; the VPS had 0 such rows) and the cron inference-account gate; a tool-name change between turns now invalidates the Claude session (`src/agents/cli-session.ts:310-314`; watch `cli session reset: … reason=prompt-tools`).
- **11.3** (live): the previous tag IS an ancestor, so no rewritten history. New cron jobs get the inference account at creation, legacy ones need `cron edit` (identity-gate steps in `CLAUDE.md` "VPS Update Recipe"); 11.1 counts a saved token as claude-cli readiness (no native login needed); `gateway ready` may never be logged, so wait on `/readyz`.
