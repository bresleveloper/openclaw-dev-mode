## Notable structural changes vs V2026.4.24 (current main)

These are NOT prompt strings, but matter for re-applying SEC-15a/SEC-98 cleanly during merge:

1. **Stable prefix is now memoized.** Lines 765–1035 wrap a large portion of the prompt build in `cacheStablePromptPrefix(stablePrefixCacheKey, () => { ... })`. The cache key includes `safetySection` derivatives indirectly (via toolLines, etc.) but NOT `safetySection` text itself by name. `isDevMode()` returns the same value within a process so the cached output is consistent — no cache poisoning. SEC-15a/SEC-98 will continue to work.
2. **`safetySection` is referenced by spread inside the cached builder** (line 884 — `...safetySection`). The const is defined OUTSIDE the cache callback (line 728), so the dev-mode branch is evaluated once per `buildAgentSystemPrompt` call.
3. **CLI Quick Reference was restructured** (lines 885–897) — the start/stop/restart list was split into "lifecycle" (status/restart only) and "operator-only, explicit user request" (start/stop). SEC-98 does not patch this section, but the new framing complements SEC-98's intent.
4. **Self-Update section's bullet list reordered** (line 906) — `config.patch` is now listed before `config.apply`, with new wording: "Config writes hot-reload when possible and use a safe restart only when required." SEC-98 strips the two cautionary lines that come before this list — those stripped lines are still present and unchanged in V2026.5.2, so the redaction will reapply cleanly.
5. **`buildExecApprovalPromptGuidance` signature changed** (line 177): added `runtimeCapabilities?: readonly string[]` param. Caller (line 866) now passes `runtimeCapabilities` instead of using the channel-plugin lookup our current main does. This will surface as a merge conflict; take upstream's shape and adapt.
6. **`buildDocsSection` signature changed** (line 446): added `sourcePath?: string` and removed the `if (!docsPath || params.isMinimal) return [];` short-circuit — section now renders even without `docsPath` (uses public mirror as fallback). No dev-mode patch interaction.
7. **Project Context section rendered ABOVE the cache boundary** (line 1009 inside the cache callback). Our current main renders it AFTER `## Workspace Files (injected)` but BEFORE `SYSTEM_PROMPT_CACHE_BOUNDARY` — same relative order, but now wrapped in the memoizer.
8. **Silent Replies moved INSIDE the cached prefix** (lines 1016–1031). Our current main also has it before the cache boundary; structurally similar.
9. **Dynamic Project Context, Webchat Canvas, Messaging, Voice, Subagent/GroupChat Context, Reactions, providerDynamicSuffix, Heartbeats, and Runtime all moved BELOW the cache boundary** (lines 1037–1106). Our current main already has Reactions, Heartbeats, Runtime below the boundary; upstream now also moves Messaging/Voice/Webchat etc. below it for cache stability.
10. **`promptContribution` plumbing throughout** (params signature line 546, normalization lines 663–672) — provider-side prompt contribution overrides specific sections (`interaction_style`, `tool_call_style`, `execution_bias`) and adds stable prefix / dynamic suffix. SEC-15a and SEC-98 do NOT use this mechanism (they are inline `isDevMode()` gates around literal sections). Worth considering for future refactors.
