### VPS Update Recipe

**By hand — there is no deploy script** (`dev-mode/vps-deploy.sh` is deleted; Ariel, 2026-11-11: "vps-deploy.sh delete"), so there is no automatic rollback either: copy the DB files first and know the Revert steps before you start. The last committed copy of the script, whose wait loop rolled a healthy 11.3 gateway back, stays in `main`'s history (`64198b5542c`). The commands:
```
cd /opt/openclaw-dev-mode && systemctl --user stop openclaw-gateway && git config core.symlinks false && git checkout -- . 2>/dev/null; git pull --ff-only origin main && git config --unset core.symlinks && CI=true pnpm install --ignore-scripts && sh dev-mode/link-dist-plugin-deps.sh && ln -sfn /opt/openclaw-dev-mode node_modules/openclaw && node --import ./scripts/tsx.mjs dev-mode/migrate-agent-dbs.mts && systemctl --user start openclaw-gateway
```
- **Stop the gateway FIRST**: a running gateway restarts itself onto the new build seconds after the pull (`Installation replaced: running … build <old>; on-disk … build <new>`, then `Cannot find module …/dist/<old-chunk>.mjs` on shutdown: expected) and refuses DBs the migration has not upgraded yet; then `openclaw gateway stop` refuses without `--force` and a manual `gateway start` fails with "another OpenClaw process owns state-lifecycle" because systemd already restarted it.
- **Copy the DB files BEFORE the migration** (the one-liner does not): `~/.openclaw/state/openclaw.sqlite*` and `~/.openclaw/agents/*/agent/openclaw-agent.sqlite*` — the previous build refuses the upgraded files. `migrate-agent-dbs.mts` is a no-op when every DB is current.
- Over SSH `systemctl --user` may need `export XDG_RUNTIME_DIR=/run/user/$(id -u)`. `git pull origin main` fetches only `main`, never an upgrade branch with upstream's history. `core.symlinks false` also covers pulls where a tracked symlink became a regular file (e.g. `CLAUDE.md`). `dev-mode/link-dist-plugin-deps.sh` recreates the `dist/extensions/<id>/node_modules` links the build makes on the build machine but never commits — without it `acpx` fails with "required dependencies are missing". Check out by commit and leave `main`'s upstream alone (`git checkout -B main origin/<branch>` re-points it; reset: `git branch -u origin/main main`).
- **The gateway is up only after BOTH** the ready signal (the `gateway ready` log line OR `curl -fsS http://127.0.0.1:18789/readyz`) AND the `Listening for WhatsApp inbound messages` line — never on the WhatsApp line alone (a scripted wait that broke on it rolled a healthy 11.3 gateway back, because 11.3 may never log `gateway ready`; see Key OpenClaw Internals). Also `systemctl --user show openclaw-gateway -p ExecMainStartTimestamp` is after the pull.
- **Never run `openclaw doctor` when deploying** (Ariel, 2026-10-16: "never run doctor when deploying as its a custom fork"): not with `--fix`, not without it, not as a step of a deploy script, not on a first install. His reason: doctor's other repairs pull the install back toward stock upstream. The gateway runs its own startup migrations on the new build (the shared state DB upgrades itself on open); agent DB schema upgrades are doctor-only upstream ("run openclaw doctor --fix to migrate session identities") → `dev-mode/migrate-agent-dbs.mts` runs just upstream's per-DB upgrade (`migrateOpenClawAgentDatabaseForMaintenance`, `src/state/openclaw-agent-db-maintenance.ts`, under `withAgentDatabaseMaintenanceLease`) from source via tsx, gateway stopped (recipe step). If a release ships another doctor-only migration or advisory that seems to matter, tell Ariel and let him decide.
- **Upgrades that add an identity gate** (11.3 pattern): right after the start, bind the legacy claude-cli crons, clear stale runtime pins and run a live cron test. (1) `openclaw cron edit <id> --model <provider/model>@anthropic:manual --json < /dev/null` for every agentTurn job that runs a Claude model (an unpinned job: its agent's primary; skip jobs pinned to non-Anthropic models and non-agentTurn jobs), then read the result back from `cron_jobs.job_json` → `inferenceBinding` (the CLI hides it). (2) Pins: find `agentRuntimeOverride: "openclaw"` in each agent DB's `session_nodes.entry_json` (`src/config/sessions/types.ts:520`) and clear it with `openclaw gateway call sessions.patch --params '{"key":"<session key>","agentId":"<id>","agentRuntime":null}' --json` (`src/gateway/sessions-patch.ts:503-505`). (3) Test: `cron add --name <t> --agent main --session isolated --at 24h --message "Reply with exactly: CRON-CLI-OK" --model anthropic/claude-haiku-5-5 --fallbacks "" --no-deliver --keep-after-run --json`, check the binding at creation, `cron run <id> --wait --wait-timeout 180s`, `cron rm <id>`.
- `openclaw agents delete --force` is refused while the gateway holds the agent's DB (`OpenClawAgentDatabaseLeaseActiveError`): stop the gateway first. A system-owned monitor job (`skill-collection-review`) can't be `cron rm`ed; 11.3 drops those jobs on load.
- Self-ref link: use `ln -sfn`. Plain `ln -sf` follows the existing link into the repo root and creates a stray `/opt/openclaw-dev-mode/openclaw-dev-mode` → itself (still there; `rm` it, it is only a symlink).

## Architecture of the Dev Mode Feature

- **Activation**: env only — `OPENCLAW_DEV_MODE=1` in `~/.openclaw/.env`, loaded by `loadDotEnv()` (`src/cli/run-main.ts`) before any command, including `gateway start/restart`. It is the ONLY flag.
- **Why not config**: an early `cli.devMode` key in `openclaw.json` broke the Zod `.strict()` schema when running stock code → gateway crash-loop. A flat `.env` can't be rejected.
- **Gate**: `src/globals.ts` `isDevMode()` = `process.env.OPENCLAW_DEV_MODE === "1"`. Extensions (can't import `src/`) check the env directly. Resolve per call, never at module load (`.env` may load after import).

## Key OpenClaw Internals

- Commander.js CLI; route-first commands (`tryRouteCli()`: `config get`, `health`, `status`) bypass Commander preAction hooks (`src/cli/program/preaction.ts`).

- Plugins: `openclaw.plugin.json` manifest + `register(api)`; discovered from `plugins.load.paths` + `extensions/`. Extension code can't import `src/` — use `openclaw/plugin-sdk/*` or read `params.cfg`.
